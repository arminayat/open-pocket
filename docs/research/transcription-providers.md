# Transcription providers for OpenPocket

Researched 2026-10-23 from official provider documentation and pricing. Scope: user-supplied API keys, downloaded MP3 recordings, German/English/multilingual transcription, and direct requests from the iPhone. No paid requests, credentials, audio uploads, browser tests, or comparative accuracy tests were performed. This is a provider-selection report; implemented behavior is documented in `docs/agents/`.

## Recommendation

Offer **OpenAI, Deepgram, AssemblyAI, ElevenLabs, and Groq** as a practical initial shortlist. They cover a familiar general-purpose API, speech-focused services with larger uploads, and inexpensive Whisper inference. This is an architectural/product recommendation, **not a market-share ranking or a verified accuracy ranking**. The first release used one batch model per provider; per-provider model choice was added on 2026-10-31 (see below). Advanced analysis, realtime streaming, and custom endpoints remain out of scope.

For short files, OpenAI is a reasonable default; Groq is the cost-oriented alternative. For long meetings, Deepgram, AssemblyAI, or ElevenLabs avoid the small direct-upload limits of OpenAI/Groq. These recommendations follow the documented limits and prices below, not a test on Pocket recordings. Actual quality must be evaluated on consented German/English samples with accents, room noise, overlapping speakers, names, and long pauses.

## Implemented request limits and lifecycle

OpenPocket caps direct uploads at **25,000,000 bytes for OpenAI and Groq**, and **500,000,000 bytes for Deepgram, AssemblyAI, and ElevenLabs**. AssemblyAI and ElevenLabs also reject recordings longer than **36,000 seconds (10 hours)** when duration is known. These are app limits, intentionally below some provider maximums; the app does not split recordings, upload them to a separate hosting service, or request extra analysis. OpenAI sends the current guide's minimal `file` + `model=gpt-transcribe` form and reads the JSON `text` field. [OpenAI request guide](https://developers.openai.com/api/docs/guides/speech-to-text)

AssemblyAI is the only resumable provider job in this implementation. Its uploaded URL is accepted only from the documented `https://cdn.assemblyai.com/upload/` origin/path. The app persists the accepted job ID before polling; reconnecting to that job uses GET without uploading or submitting again. A submitted job's short receipt is allowed to finish within its request deadline even after local cancellation, so a received ID can be saved. If no receipt arrives, the outcome remains uncertain. There are no automatic retries of billable requests and no automatic remote DELETE calls. Final provider responses are normalized to plain text; speaker labels and timestamps are not exposed by this first implementation.

## Adoption evidence and deferred providers

Primary sources can establish production usage but not comparative market share. AssemblyAI's own customer material names Zoom, Fireflies, Granola, and others; that supports real adoption, not a rank. No defensible current market-share ordering across these five was established. OpenAI/Groq-compatible interfaces or developer mindshare likewise do not prove transcription adoption. [AssemblyAI customer material](https://www.assemblyai.com/pricing)

Google Cloud Speech-to-Text, Azure AI Speech, and Amazon Transcribe remain candidates for users already invested in those clouds. They are deferred from the initial simple-key experience pending a separate review of resource/project/region configuration, authorization, long-file storage, pricing, and privacy. This report makes no claim that they are less accurate or less popular. [Google documentation](https://cloud.google.com/speech-to-text/docs), [Azure documentation](https://learn.microsoft.com/azure/ai-services/speech-service/speech-to-text), [Amazon documentation](https://docs.aws.amazon.com/transcribe/latest/dg/what-is.html)

## Privacy and integration constraints

- **All five are cloud processing.** Choosing Transcribe must make the selected provider and use of the user's billable account clear. Keys belong in the device Keychain, never source code, diagnostics, transcript JSON, or shared files. Saving a key must not upload a recording. These are recommended application invariants, not provider guarantees.
- **Deepgram:** requests participate in model improvement by default. Send `mip_opt_out=true`; documented opted-out audio/transcripts are retained only while processing, while usage metadata remains. Full regional residency also requires a regional endpoint; do not claim EU residency merely from opt-out. [Data policy](https://developers.deepgram.com/trust-security/your-data)
- **AssemblyAI:** model training can apply under the contract unless opted out, using EU servers, or covered by a BAA. Async retention differs from streaming/sync: uploaded files and final transcripts have separate rules, TTLs, and deletion behavior. The app preserves a job ID to retrieve results without resubmitting billable work, but does not automatically delete provider artifacts. Users must manage provider retention/training settings and remote deletion through their account. The provider offers `DELETE /v2/transcript/{id}` for transcript and associated uploaded-file removal; that capability is not implemented here, and does not establish cancellation of processing or charges. Local cancellation or key removal is not remote deletion. [Retention and training](https://www.assemblyai.com/docs/data-retention-and-model-training), [delete reference](https://www.assemblyai.com/docs/pre-recorded-audio/api-reference/transcripts/delete)
- **ElevenLabs:** Zero Retention Mode is an enterprise capability enabled with `enable_logging=false`; do not promise it for arbitrary user accounts or unconditionally send an enterprise-only option. Standard account retention/training settings must be reviewed by the account owner. [Zero Retention Mode](https://elevenlabs.io/docs/eleven-api/resources/zero-retention-mode)
- **Groq:** inference content is not retained by default, but reliability/abuse investigations may retain inputs/outputs for up to 30 days unless the organization opts out. Usage metadata remains. [Data policy](https://console.groq.com/docs/your-data)
- **OpenAI:** use a separately billed API key; existing ChatGPT sign-in does not provide transcription. Avoid presenting general API privacy assumptions as a universal retention guarantee; account and endpoint data controls govern uploads. [ChatGPT connection limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations), [API data controls](https://developers.openai.com/api/docs/guides/your-data)
- **Model lifecycle matters:** OpenAI's old Whisper/4o transcription models shut down February 26, 2027; choose `gpt-transcribe`. AssemblyAI's `universal-3-pro` has been replaced and requests can fail; use `universal-3-5-pro` or the explicitly supported current selection. [OpenAI guide](https://developers.openai.com/api/docs/guides/speech-to-text), [AssemblyAI changelog](https://www.assemblyai.com/changelog)

## Model discovery (researched 2026-10-31)

Only Deepgram's listing marks speech models with typed fields. OpenAI and Groq list the models a key can use, but identify transcription models only by ID. ElevenLabs and AssemblyAI have no usable speech-model listing.

- **OpenAI:** `GET /v1/models` (Bearer). Keep `whisper*` and `gpt-*transcribe*`; exclude Realtime-only `gpt-live-transcribe` and `*-diarize`, which needs `chunking_strategy`. `shutdown_date` labels retirements. `whisper-1`, `gpt-4o(-mini)-transcribe` and diarize are announced for shutdown on 2027-02-26, replaced by `gpt-transcribe`. Sources: [models list](https://developers.openai.com/api/reference/resources/models/methods/list), [transcriptions](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/methods/create), [deprecations](https://developers.openai.com/api/docs/deprecations).
- **Groq:** `GET /openai/v1/models` (Bearer). Keep `whisper*` entries with `active` not false. `distil-whisper-large-v3-en` was retired in August 2025. Sources: [API reference](https://console.groq.com/docs/api-reference), [deprecations](https://console.groq.com/docs/deprecations).
- **Deepgram:** `GET /v1/models` (`Token`). Use the `stt` entries with `batch: true`, deduplicated by `canonical_name`. Flux is streaming-only. Omitting `model` on `/v1/listen` defaults to `base-general`, so always send it. Sources: [models list](https://developers.deepgram.com/reference/manage/models/list), [models overview](https://developers.deepgram.com/docs/models-languages-overview).
- **ElevenLabs:** `/v1/models` lists TTS capability flags only; Scribe IDs are fixed (`scribe_v2`, `scribe_v2_medical`; `scribe_v2_realtime` is WebSocket-only, `scribe_v1` deprecated). The app uses `/v1/models` only to verify the key. Source: [models overview](https://elevenlabs.io/docs/overview/models).
- **AssemblyAI:** no listing endpoint. `speech_models` array (singular `speech_model` deprecated); the app offers automatic (`universal-3-5-pro` then `universal-2`), or either alone. The key is verified with `GET /v2/transcript?limit=1`. Sources: [select the model](https://www.assemblyai.com/docs/pre-recorded-audio/select-the-speech-model), [submit](https://www.assemblyai.com/docs/api-reference/transcripts/submit).

Not verified from a primary source: whether ElevenLabs lists Scribe models in `/v1/models` (third-party code suggests not); Groq's and ElevenLabs' exact invalid-key status codes (likely 401); and other `response_format` values for `gpt-transcribe` (the app sends no format for OpenAI).

## Acceptance boundary

For the first release: add/remove/select provider keys; explicitly transcribe a locally downloaded recording; reject unsupported size before upload; show progress and actionable errors; persist/display/share a successful transcript; prevent duplicate in-flight jobs; never automatically retry an ambiguous billable submission. Do not silently split or truncate recordings. If an upload exceeds the chosen provider limit, explain the limit and allow selecting a provider with a larger supported limit. Unit/contract tests prove request construction and state handling; only a separately authorized real-device request proves provider acceptance and recording quality.
