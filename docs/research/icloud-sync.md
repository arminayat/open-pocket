# iCloud Drive sync for OpenPocket

Researched 2026-10-23 against Apple and Expo primary sources. This report describes platform requirements and recommended boundaries, not verified provider state or implemented behavior. No Apple account settings, portal registrations, provisioning profiles, or real iCloud files were changed. No browser/device sync tests were run.

## Recommendation and guarantees

Use an **opt-in iCloud Documents container** for recording audio and portable transcript files, with local copies retained for playback. That makes files accessible through iCloud Drive on devices using the same Apple account without requiring another app backend. Apple distinguishes iCloud Documents from CloudKit; the former fits user-visible MP3/text files and does not require a CloudKit record schema. [Apple service configuration](https://developer.apple.com/documentation/xcode/configuring-icloud-services), [Apple document sample](https://developer.apple.com/documentation/uikit/synchronizing-documents-in-the-icloud-environment)

A simple container integration can submit files to Apple's sync system, discover remote metadata, request downloads, and report local item transfer state. It cannot make a coordinated local write into a cross-device transaction, prove another device has downloaded a file, or guarantee prompt propagation. “Saved to iCloud folder,” “upload pending,” and “uploaded to iCloud” must remain separate states. A “last sync” timestamp should identify the app's last reconciliation, not imply all devices agree. [Upload status](https://developer.apple.com/documentation/foundation/urlresourcekey/ubiquitousitemisuploadedkey), [Download status](https://developer.apple.com/documentation/foundation/urlresourcekey/ubiquitousitemdownloadingstatuskey), [Conflict semantics](https://developer.apple.com/documentation/foundation/nsfileversion/isconflict)

If preserving the current generated app's identity is intended, make that identity durable in `app.json` and use the matching container consistently. ## Required local configuration and provisioning

For one chosen identifier such as `iCloud.<settled-bundle-id>`, persist these through app config or a small config plugin:

| Location | Required value |
| --- | --- |
| Entitlement `com.apple.developer.icloud-container-identifiers` | Array containing the selected registered container |
| Entitlement `com.apple.developer.ubiquity-container-identifiers` | Same container array |
| Entitlement `com.apple.developer.icloud-services` | `['CloudDocuments']` |
| `Info.plist` `NSUbiquitousContainers[container]` | `NSUbiquitousContainerIsDocumentScopePublic: true`, `NSUbiquitousContainerName: 'OpenPocket'`, `NSUbiquitousContainerSupportedFolderLevels: 'Any'` |
| Container layout | User-visible documents in the container's `Documents/` directory |

The entitlement mapping is documented by [Apple](https://developer.apple.com/documentation/xcode/configuring-icloud-services); visible-folder metadata is documented in [Apple's iCloud Drive guide](https://developer.apple.com/library/archive/documentation/General/Conceptual/iCloudDesignGuide/Chapters/DesigningForDocumentsIniCloud.html). Public document scope means accessible to the account owner through other apps, not public access on the internet. Do not add CloudKit, push notifications, or key-value storage merely for filesystem sync; those are separate services. [Service entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.icloud-services)

Apple requires the container to be registered, associated with the App ID, and present in signing entitlements/provisioning. Changing App ID capabilities invalidates affected provisioning profiles and requires regeneration; Xcode automatic signing can perform account mutations. Membership and role determine available capabilities. [Create container](https://developer.apple.com/help/account/identifiers/create-an-icloud-container), [Enable capabilities](https://developer.apple.com/help/account/identifiers/enable-app-capabilities), [Capability availability](https://developer.apple.com/help/account/capabilities/capabilities-overview/)

For Files/Finder visibility, increment `CFBundleVersion` when changing container metadata, and place at least one document in `Documents/`. An empty, unused container may not appear. All devices must use the same Apple account with iCloud Drive enabled. [Apple sample](https://developer.apple.com/documentation/uikit/synchronizing-documents-in-the-icloud-environment), [Metadata refresh guidance](https://developer.apple.com/library/archive/qa/qa1893/_index.html)

Expo's `usesIcloudStorage` is a configuration flag, not a sync engine. `ios.entitlements` and `ios.infoPlist` or a config plugin can persist native configuration. A new development build is required; a JS update cannot add capabilities. Expo's DocumentPicker plugin offers `iCloudContainerEnvironment` for Ad Hoc signing, but environment must match the signing configuration rather than being hard-coded indiscriminately. Installing DocumentPicker solely to obtain those entitlements is unnecessary if a native sync module already owns access. [Expo app config](https://docs.expo.dev/versions/latest/config/app/), [Expo DocumentPicker configuration](https://docs.expo.dev/versions/latest/sdk/document-picker/)

## Runtime ownership and safety

- **Availability and account identity:** use `FileManager.ubiquityIdentityToken` (nil means unavailable) and observe `NSUbiquityIdentityDidChange`; compare archived tokens using `isEqual`. A non-nil token alone does not establish container access. Resolve `url(forUbiquityContainerIdentifier:)` off the main thread and handle nil. [Identity token](https://developer.apple.com/documentation/foundation/filemanager/ubiquityidentitytoken), [Identity change notification](https://developer.apple.com/documentation/foundation/nsnotification/name-swift.struct/nsubiquityidentitydidchange), [Container lookup](https://developer.apple.com/documentation/foundation/filemanager/url(forubiquitycontaineridentifier:))
- **Consent isolation (recommended app policy):** keep sync opt-in local and bind it to the consenting iCloud identity. On sign-out/change, invalidate in-flight generations, stop queries, discard cached cloud URLs, and pause outbound work. Require a fresh opt-in before sending old local recordings into a different account. Recheck identity immediately before mutations and before accepting async results. Never sync API keys, ChatGPT/Pocket tokens, recorder credentials, or account identity tokens in visible files.
- **Discovery:** use `NSMetadataQuery` with the ubiquitous Documents scope and a predicate restricted to this app's container/schema. A directory scan alone misses documents whose metadata has arrived before their bytes. Observe initial gathering and updates; disable query updates while reading results, then re-enable them. Do not persist cloud absolute paths as identity. [Apple document discovery](https://developer.apple.com/documentation/uikit/synchronizing-documents-in-the-icloud-environment), [File management guide](https://developer.apple.com/library/archive/documentation/FileManagement/Conceptual/FileSystemProgrammingGuide/iCloud/iCloud.html)
- **Downloading:** `startDownloadingUbiquitousItem(at:)` requests work; returning successfully does not mean bytes are ready. Observe download status/error and coordinate the eventual read. Keep metadata-only items pending instead of treating them as corrupt or deleted; interrupted/offline downloads can be retried without inventing a transcript or empty MP3. [Download request](https://developer.apple.com/documentation/foundation/filemanager/startdownloadingubiquitousitem(at:)), [Download state](https://developer.apple.com/documentation/foundation/urlresourcekey/ubiquitousitemdownloadingstatuskey)
- **Writes and reads:** use `NSFileCoordinator` per operation on a background queue; keep heavy copying/validation off the main thread. Coordination covers local processes but does not merge offline edits from different devices. Avoid waiting for cloud transfer completion while holding a coordinated accessor. [Coordinator](https://developer.apple.com/documentation/foundation/nsfilecoordinator), [Filesystem guidance](https://developer.apple.com/documentation/foundation/improving-performance-and-stability-when-accessing-the-file-system), [Upload-status warning](https://developer.apple.com/documentation/foundation/urlresourcekey/ubiquitousitemisuploadedkey)
- **Conflict/data-loss prevention (recommended app policy):** prefer immutable recording files and uniquely named transcript revisions over one shared mutable library index. Validate imported metadata and file bounds before adding it to local storage; ignore temporary/incomplete files. Do not silently overwrite different bytes at an existing identity or equate a missing cloud listing with deletion. Preserve conflicting revisions and report them; mark `NSFileVersion` conflicts resolved only after their contents are safely handled. [Conflict versions](https://developer.apple.com/documentation/foundation/nsfileversion/isconflict), [Resolution and cleanup](https://developer.apple.com/documentation/foundation/nsfileversion/isresolved)
- **Opt-out (recommended app policy):** turning sync off stops new app reconciliation; retain local recordings and explain that cloud files already handed to iCloud remain there. Do not claim it cancels every OS upload or deletes remote data. Cloud deletion and propagation would need a separate explicitly designed feature.

## Opening the folder and acceptance

Use the documented `UIDocumentPickerViewController` with `directoryURL` pointing to the container's Documents folder for an in-app “Browse iCloud files” action. Apple documents this as a preferred starting directory, not a guaranteed jump in the standalone Files app. A folder picker uses `.folder`; a file browser can use supported document types. No documented standalone Files deep-link contract was established by this research, so avoid relying on `shareddocuments://`. Explain the manual route as Files → iCloud Drive → OpenPocket; on Mac, Finder → iCloud Drive → OpenPocket. [Directory hint](https://developer.apple.com/documentation/uikit/uidocumentpickerviewcontroller/directoryurl), [Directory picker](https://developer.apple.com/documentation/uikit/providing-access-to-directories)

Minimum proof before claiming live sync: signed physical-device build with matching entitlements/profile; opt-in creates a visible folder; a second same-account device discovers a metadata-only item and downloads correct bytes; offline upload later progresses; account switch cannot receive the previous account's queued uploads; concurrent edits preserve both contents; disabling sync leaves local audio usable. Synthetic tests and compilation can establish policy/request logic, not Apple propagation, provisioning, or Files/Finder visibility.
