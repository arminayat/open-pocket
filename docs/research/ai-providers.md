# AI providers for transcript summaries and titles

Researched 2026-11-01 from official provider documentation, API references, terms, and SDK source. Scope: a user-configured "AI provider" that turns a saved transcript into (1) a summary and (2) a short title, with requests sent directly from the iPhone and no OpenPocket backend. Transcripts are long: one hour is roughly 8–10k words or 12–15k tokens, and multi-hour recordings exist. No paid requests, credentials, model calls, browser tests, or quality comparisons were run. This note helps choose providers. Implemented behavior belongs in `docs/agents/`. Where a page could not be read directly, the note says so.

## Recommendation

**Do first**

1. **ChatGPT plan through the existing Sign in with ChatGPT (SIWC) connection.** The app already requests the plan-usage scopes (`offline_access resource.invoke chatgpt.tokens.use.direct`, see `src/lib/chatgpt/types.ts`) and stores rotating tokens. Inference is a documented `POST https://api.openai.com/v1/responses` with the access token. Signed-in users need no setup and pay nothing extra, and the app needs no new auth flow. Risks: the flow is a preview with strict request rules (`stream: true`, `store: false`, no `max_output_tokens`/`temperature`), and usage limits can fail a request mid-stream. Its documented scope is "open-source and locally hosted apps", and the docs do not say how that applies to App Store distribution. Fall back to an API key when plan usage is unavailable, as OpenAI suggests.
2. **OpenAI API key, reusing the transcription key.** This uses the same Responses endpoint and nearly the same request code as option 1, minus the SIWC restrictions. `gpt-6-luna` ($0.10/$0.50 per MTok, 1.05M context) makes a one-hour summary cost fractions of a cent (arithmetic, not a quote).
3. **Anthropic Claude API key.** This adds a second major vendor with a simple key and a 1M context. `claude-haiku-5-5` is the cheap default and `claude-sonnet-5-5` the quality option. Conversation content is not retained by default. Watch for the `anthropic-workspace-id` requirement on keys that are not scoped to a workspace.

**Later**

- **OpenRouter OAuth PKCE.** A one-tap flow returns a user-owned key with no copy-paste and gives access to many models, some free. Do it after the direct providers, because the privacy routing flags must be set on every request and custom-scheme callbacks are undocumented. The documented localhost callback can reuse the app's existing loopback relay.
- **Apple Foundation Models.** The on-device model is free, private, and works offline, but its 4,096-token window needs map-reduce for any real recording. **Private Cloud Compute** (iOS 27, 32K window, no API cost) is attractive. It requires Apple's entitlement and Small Business Program enrollment, and each user has a daily limit.
- **Groq key reuse** (`openai/gpt-oss-20b`/`-120b`, 131K context, Chat Completions API) and the **AssemblyAI LLM Gateway** (reuses the AssemblyAI key, OpenAI-compatible). Both are cheap additions for users who already have those keys.
- **Gemini API key.** It works, but the free tier trains on content and allows human review, so make paid-tier status clear before sending private transcripts.

**Avoid or not possible**

- **Claude.ai Pro/Max/Ultra subscription login in a third-party app.** Anthropic explicitly prohibits it.
- **AssemblyAI LeMUR.** It was retired on 2026-03-31.
- **Arbitrary custom or LAN endpoints (Ollama, LM Studio) in v1.** They contradict the app's fixed trusted-URL invariant, an explicit non-goal. See the integration constraints.
- **DeepSeek.** Its privacy policy says data is stored on servers in the PRC. That is a poor default for private meeting recordings.

## Sign in with ChatGPT (ChatGPT plan usage)

- **What is documented.** An open-source app "can request permission to use the user's ChatGPT plan for eligible Responses API requests". This does not grant access to the user's ChatGPT conversations. The docs cover "open-source and locally hosted apps". Paid or remotely hosted apps must use an interest form instead. [Plan usage overview](https://developers.openai.com/siwc/token-sharing-open-source)
- **Scopes and gating.** Identity scopes are `openid profile email`. Plan-usage scopes are `offline_access resource.invoke chatgpt.tokens.use.direct`, with `resource=https://api.openai.com/v1`. Check the token response for `chatgpt.tokens.use.direct` "before proceeding to inference". "A valid ID token alone does not authorize ChatGPT plan usage." Access tokens last 1 hour. Refresh tokens last 30 days and rotate. [Sign-in](https://developers.openai.com/siwc/token-sharing-open-source/sign-in), [Token reference](https://developers.openai.com/siwc/token-sharing-open-source/token-reference)
- **Endpoint and models.** Inference is `POST https://api.openai.com/v1/responses` with `Authorization: Bearer <access token>`. The docs say not to use ChatGPT's `backend-api`. Models come from `GET https://api.openai.com/v1/models` with the same token. Keep entries with `visibility == "list"`, keep server order, show `display_name`, send `slug` as `model`, and refresh the list when the account changes. The only model named is `gpt-6.1-sol`. [Models and inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)
- **Request rules.** Every request must set `store: false` and `stream: true`. Treat a response as complete only after `response.completed`, and handle `response.failed`, `response.incomplete`, and interrupted streams. Put the system prompt in `instructions` or developer messages, because system message items are rejected. Unsupported fields include `max_output_tokens`, `temperature`, `top_p`, `truncation`, `metadata`, `background`, and `previous_response_id`. Audio input, the Files API, and the transcription API are not supported. [Preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)
- **Limits and errors.** The documented codes are `subscription_sharing_usage_limit_exceeded` (429, which can be an app-specific cap rather than plan exhaustion), `subscription_sharing_usage_unavailable` (503, retry later with bounded backoff), and `subscription_sharing_user_not_eligible` (403). "OpenAI does not silently switch the request to another billing path." The docs suggest offering the user's own API key instead. No numeric rate limits are published. [Errors and recovery](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery)
- **Plans and billing.** Eligible requests draw on "usage included in the user's ChatGPT plan or available credits". The quickstart says "Eligible ChatGPT Plus and Pro users" and "plan usage is available to all open-source partners". [Quickstart](https://developers.openai.com/siwc/quickstart) The help article [Using your ChatGPT plan in other apps](https://help.openai.com/en/articles/20001542-using-your-chatgpt-plan-in-other-apps-and-sites) returned HTTP 403 to the fetcher and was read only through search excerpts. Those excerpts say supported open-source tools are available to all ChatGPT users, Go/Plus/Pro can use plan usage in commercial apps, and users can cap per-app weekly usage. **Treat the tier details as unverified.**
- **App fit.** OpenPocket's code is MIT-licensed and runs locally on the phone, which matches "open-source and locally hosted" on its face. Whether an App Store build counts is **not addressed** in the docs (open question). Use is also subject to the general [OpenAI policies](https://openai.com/policies). The app can already read SSE (`src/lib/account/http.ts`), and `expo/fetch` exposes `response.body.getReader()`. [expo/fetch](https://docs.expo.dev/versions/latest/sdk/expo/)

## OpenRouter

- **OAuth PKCE.** Send the user to `https://openrouter.ai/auth?callback_url=…&code_challenge=…&code_challenge_method=S256`, then `POST https://openrouter.ai/api/v1/auth/keys` with `code` and `code_verifier`. The response contains `key`, a user-controlled API key billed to the user's credits. Codes expire after 10 minutes. Optional parameters are `key_label`, `workspace_id`, and `state`. "Localhost callbacks are supported on any port." For production, a public URL is recommended. A headless mode with no callback shows a code for the user to copy. [OAuth guide](https://openrouter.ai/docs/guides/overview/auth/oauth.md)
- **Native mobile.** Custom URL schemes such as `openpocket://` are **not documented**. Two supported routes are an `http://127.0.0.1:<port>` callback through the app's existing `PocketOAuthLoopback` relay (`modules/pocket-wifi/ios/PocketOAuthLoopback.swift`) and the headless code flow. Inference: whether OpenRouter accepts a custom scheme directly must be tested. Spending limits and expiry on OAuth-issued keys are not documented.
- **Models and pricing.** `GET https://openrouter.ai/api/v1/models` returns `id`, `name`, `context_length`, `pricing.prompt`/`completion` (USD per token, "0" means free), `supported_parameters`, and `top_provider.max_completion_tokens`. [Models](https://openrouter.ai/docs/guides/overview/models) OpenRouter passes provider pricing through "without any markup" but charges a fee on credit purchases. `:free` variants allow 50 requests per day, or 1,000 per day after buying at least 10 credits. [FAQ](https://openrouter.ai/docs/faq)
- **Privacy.** OpenRouter logs metadata (timestamps, model, token counts) and does "zero logging of your prompts/completions … unless you opt-in". [FAQ](https://openrouter.ai/docs/faq) Per request, `provider.data_collection: "deny"` (default `"allow"`) restricts routing to providers that don't collect data, and `provider.zdr: true` restricts it to ZDR endpoints. [Provider routing](https://openrouter.ai/docs/guides/routing/provider-selection) ZDR excludes tools and plugins. Endpoints with unknown policies are assumed to retain and train. CSAM screening of all traffic, including ZDR traffic, started 2026-10-27. [ZDR](https://openrouter.ai/docs/guides/features/zdr) Account settings control routing to providers that train, with separate settings for free and paid models. [Logging](https://openrouter.ai/docs/guides/privacy/logging) Recommendation: always send both flags, and expect some free models to become unavailable as a result.

## Anthropic Claude API key

- **Request.** `POST https://api.anthropic.com/v1/messages` with `Authorization: Bearer <key>` (or the legacy `x-api-key`), `anthropic-version`, and `content-type: application/json`. A key **not scoped to a workspace** must also send `anthropic-workspace-id`, or the request fails with a 400 whose message names the header. Keys can be scoped to a workspace when created, and keys can be set to expire. [API overview](https://platform.claude.com/docs/en/api/overview), [Authentication](https://platform.claude.com/docs/en/manage-claude/authentication) For v1, ask users for a workspace-scoped key and map that 400 to a clear message.
- **Browser header.** The TypeScript SDK blocks "browser-like environments" unless `dangerouslyAllowBrowser` is set. [SDK source](https://github.com/anthropics/anthropic-sdk-typescript/blob/main/src/client.ts) The `anthropic-dangerous-direct-browser-access` header relates to browser CORS. No official doc for it was found. Inference: CORS does not apply to native `fetch` in React Native, so OpenPocket should not need the header.
- **App Attest.** This lets iOS apps call Claude without shipping a key, but it bills **the developer's** workspace. [Authentication](https://platform.claude.com/docs/en/manage-claude/authentication) That doesn't fit a bring-your-own-key app with no developer billing.
- **Models.** All current models have a 1M context and 128K max output. `claude-haiku-5-5` costs $0.10/$0.50 per MTok for prompts up to 100K tokens and $0.50/$2.50 above 100K. Its tokenizer counts about 30% more tokens than Haiku 4.5. `claude-sonnet-5-5` costs $2/$10, `claude-opus-5-5` $4/$20. Haiku 5.5 rejects `temperature`, `top_p`, and `top_k`. [Models overview](https://platform.claude.com/docs/en/about-claude/models/overview), [Haiku 5.5](https://platform.claude.com/docs/en/models/haiku-5-5/overview) `GET /v1/models` returns `max_input_tokens`, `max_tokens`, `capabilities`, and `line`, and pages with `after_id`/`has_more`. [API overview](https://platform.claude.com/docs/en/api/overview)
- **Retention.** "Conversation content … is not retained by default." The exception is Covered Models (Fable 5.1, Mythos 5.1, Fable 5, Mythos 5), which require 30-day retention. Retained data is never used for training without express permission. [API and data retention](https://platform.claude.com/docs/en/manage-claude/api-and-data-retention) Avoid offering Covered Models as defaults.
- **Subscription login.** "Anthropic does not permit third-party developers to offer Claude.ai login into their own applications, or to route requests through Free, Pro, Max, or Ultra plan credentials on behalf of their users." Developers also "may not collect, store, or intermediate Claude.ai credentials or session tokens". [Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance) **Not possible.**

## OpenAI API key

- **Reuse.** The transcription key in Keychain can be offered for summaries after a separate explicit choice, because summaries are a different billable use. Use `POST /v1/responses` (or Chat Completions) and `GET /v1/models`. The models list is already allowlisted in `src/lib/transcription/request.ts`.
- **Models.** `gpt-6-luna` costs $0.10/$0.50 and is "most efficient … high-volume". `gpt-6.1-terra` costs $1/$5. `gpt-6.1-sol` costs $2/$10 and balances quality and cost. `gpt-6-astra` costs $10/$50. All have a 1.05M context and 128K output. [Models](https://developers.openai.com/api/docs/models) `GET /v1/models` lists IDs only, so the app must filter text models by ID.
- **Retention.** API data is not used for training unless the customer opts in. `/v1/responses` and `/v1/chat/completions` keep 30-day abuse-monitoring logs. Responses keeps 30-day application state when `store` is true. ZDR "subject to prior approval". [Your data](https://developers.openai.com/api/docs/guides/your-data) Always send `store: false`. The default value of `store` was not confirmed from the reference.

## Apple Foundation Models (on-device and Private Cloud Compute)

- **On-device.** The model is iOS 26+. `SystemLanguageModel.availability` can be unavailable for `deviceNotEligible`, `appleIntelligenceNotEnabled`, or `modelNotReady`. [Unavailable reasons](https://developer.apple.com/documentation/foundationmodels/systemlanguagemodel/availability-swift.enum/unavailablereason) `contextSize` covers input and output and is back-deployed to 26.4. [contextSize](https://developer.apple.com/documentation/foundationmodels/systemlanguagemodel/contextsize) `supportedLanguages` and `supportsLocale(_:)` check languages. [supportedLanguages](https://developer.apple.com/documentation/foundationmodels/systemlanguagemodel/supportedlanguages)
- **Context window.** "4096 tokens per language model session". The guidance for long text is to chunk it, summarize each chunk in a new session, and combine the results. `maximumResponseTokens` can produce malformed output. [TN3193](https://developer.apple.com/documentation/technotes/tn3193-managing-the-on-device-foundation-model-s-context-window) A WWDC26 sample comments "8192 on 27.0 (newer devices)", while WWDC Q&A reportedly said the limit is still 4096. **Read `contextSize` at runtime and don't hard-code it.** [WWDC26 PCC session](https://developer.apple.com/videos/play/wwdc2026/319/), [What's new](https://developer.apple.com/videos/play/wwdc2026/241/) A one-hour transcript (about 15K tokens) needs at least four to eight map calls plus reduce calls (inference from the numbers above).
- **Devices and languages.** iOS 27 Apple Intelligence devices start at iPhone 15 Pro and the iPhone 16 family. German and English are supported languages, and the new features are not yet available in China. These details come from Apple newsroom/support pages read through search results ([support](https://support.apple.com/en-au/121115), [newsroom Oct 2026](https://www.apple.com/newsroom/2026/10/siri-ai-is-available-in-more-languages-starting-today/)). Verify at runtime with the availability APIs.
- **iOS 27 Private Cloud Compute.** `LanguageModelSession(model: PrivateCloudComputeLanguageModel())` has a 32K context, and reasoning tokens count against it. The developer has no token cost and needs no keys. "Each user gets a daily limit", higher with iCloud+, exposed through `quotaUsage`. It requires an Apple Intelligence device and a network connection, and "user data is never stored". [WWDC26 session 319](https://developer.apple.com/videos/play/wwdc2026/319/) Eligibility requires App Store Small Business Program enrollment, fewer than 2M first-time downloads, and the PCC entitlement. If eligibility lapses, the developer must migrate within 6 months. Daily limits vary, and "expanded access … for a fee in the future". [Apple PCC](https://developer.apple.com/private-cloud-compute/) A 32K window covers about one to two hours of transcript in one request (inference).
- **React Native.** A small local Expo module in Swift, following the `modules/pocket-*` pattern, is the low-dependency path. Expo documents Xcode 26.4 or later for its own Foundation Models wrapper. Inference: PCC also needs the iOS 27 SDK. Expo's first-party `expo-ai` wraps Foundation Models, but it is **alpha** and documented for the *next* SDK, not SDK 57. It does not mention PCC. [expo-ai](https://docs.expo.dev/versions/unversioned/sdk/ai/) Callstack's `@react-native-ai/apple` is a community alternative. [Callstack](https://www.callstack.com/blog/on-device-apple-llm-support-comes-to-react-native) iOS 27 also adds a `LanguageModel` protocol, and Anthropic and Google are publishing Swift packages for it. Those take user tokens, so they don't remove the need for keys. [What's new](https://developer.apple.com/videos/play/wwdc2026/241/)

## Other options (brief)

- **Groq.** Production chat models are `openai/gpt-oss-20b` ($0.075/$0.30) and `openai/gpt-oss-120b` ($0.15/$0.60), both with a 131,072 context. Llama models are listed as "Contact Sales". [Models](https://console.groq.com/docs/models) Groq does not retain inference data by default but may keep logs up to 30 days for reliability or abuse. Any customer can enable ZDR. [Your data](https://console.groq.com/docs/your-data) The model list endpoint is already allowlisted.
- **AssemblyAI LLM Gateway.** OpenAI-compatible `https://llm-gateway.assemblyai.com/v1/chat/completions` (EU: `llm-gateway.eu.assemblyai.com`) offers 25+ models (Claude, GPT, Gemini…). Its auth header carries the AssemblyAI key. [Overview](https://www.assemblyai.com/docs/llm-gateway/overview) LeMUR stopped working on 2026-03-31, per the changelog read through a search excerpt. [Changelog](https://www.assemblyai.com/changelog)
- **Mistral.** The free Studio mode may use inputs and outputs for training unless the user opts out. ZDR is a separate paid control. [Opt-out](https://help.mistral.ai/en/articles/455207-can-i-opt-out-of-my-input-or-output-data-being-used-for-training), [ZDR](https://docs.mistral.ai/admin/monitor-comply/zero-data-retention)
- **xAI.** Requests and responses are kept encrypted for 30 days for abuse auditing and are not used for training without permission. Optional ZDR is available. [Security FAQ](https://docs.x.ai/developers/faq/security)
- **DeepSeek.** The Open Platform policy says information is kept on servers in the PRC. [Privacy policy](https://cdn.deepseek.com/policies/en-US/deepseek-privacy-policy.html)
- **Generic OpenAI-compatible endpoint (Ollama/LM Studio).** Ollama serves `http://localhost:11434/v1/` with `/v1/chat/completions`, `/v1/responses` (stateless), and `/v1/models`. It ignores the key locally. [Ollama](https://docs.ollama.com/api/openai-compatibility) Reaching it from a phone needs a LAN IP over plain HTTP, and since iOS 17 ATS blocks IP addresses by default, so this needs `NSAllowsLocalNetworking` or per-IP exceptions. [ATS](https://developer.apple.com/documentation/bundleresources/information-property-list/nsapptransportsecurity/nsallowslocalnetworking) The security cost is that transcripts and any bearer key travel unencrypted to a host the app cannot authenticate. Allowing arbitrary hosts also breaks the trusted-URL allowlist, and anyone on the network could spoof the server. Defer it until it gets its own threat model and explicit per-host consent.

## Integration constraints for OpenPocket

- **No backend.** Every option must be a direct HTTPS call with the user's credential. SIWC tokens already refresh in `ChatGPTProvider`. Store API keys and OpenRouter OAuth keys in device-only Keychain, as transcription keys are. Never log keys or put transcripts in diagnostics.
- **Trusted URL allowlist.** Extend the pattern in `assertTrustedTranscriptionUrl` with an AI-specific allowlist of exact origins and paths, such as `api.openai.com/v1/responses`, `api.anthropic.com/v1/messages`, `openrouter.ai/api/v1/{chat/completions,responses,models,auth/keys}`, `generativelanguage.googleapis.com/v1beta/models…`, and `api.groq.com/openai/v1/chat/completions`. Keep the redirect, credential, and fragment rejections.
- **Response bounds.** Keep a byte cap on bodies, as `MAX_RESPONSE_BYTES` does for transcription. Summaries are small, so a much lower cap than 8 MB is reasonable (recommendation). SIWC requires SSE, so bound the accumulated stream and accept output only after `response.completed`. Other providers don't need streaming. Validate that the extracted title and summary are non-empty strings within length limits before saving.
- **Long transcripts.** With the suggested cloud models (131K–1M context), one request covers many hours. 131K tokens is about 9–10 hours at 12–15K tokens per hour (arithmetic). Use a single request when the estimated tokens, at about 4 characters per token plus margin, fit the model's documented limit. Otherwise map-reduce over chunks at speaker or paragraph boundaries, then summarize the summaries. Apple on-device always needs map-reduce, and PCC above about 1–2 hours. Haiku 5.5 bills more above 100K-token prompts.
- **Title.** Generate the title from the finished summary rather than the full transcript. It's cheaper and works for map-reduce too. Alternatively, ask for both in one response. SIWC rejects `max_output_tokens`, so control length in the instructions. Whether SIWC supports structured-output `text.format` is unverified, so parse defensively.
- **Billing safety.** Mirror the transcription invariants: require an explicit user action or a once-confirmed per-provider automatic setting, never retry a billable request automatically, and prevent duplicate in-flight jobs. On SIWC usage errors, stop and offer another provider rather than switching silently.

## Observed on device (2026-11-01)

- SIWC `POST /v1/responses` rejects a string `input` with HTTP 400 `{"detail":"Input must be a list"}`; a one-item message list (`[{ role: "user", content: [{ type: "input_text", text }] }]`) works.
- The plan's model list returned `gpt-6.1-terra` first; `gpt-6.1-sol` was not used.
- The stream's `response.completed` event arrived without output text; the text was only in the `response.output_text.*` events.
