# Architecture and tools

Source repository: [arminayat/open-pocket](https://github.com/arminayat/open-pocket), private, default branch `main` (created 2026-11-04). No GitHub Actions workflow or automatic deployment is configured; TestFlight remains a separate manual command. Pre-push checks on 2026-11-04 passed TypeScript, lint, 177 Node tests, and all four native helper suites. On 2026-11-22 `npx expo install --fix` aligned the Expo packages and `npm run check` passed end to end (typecheck, lint, 177 tests, `expo install --check`) with all four native suites. The expo-sharing and expo-splash-screen plugin entries that `--fix` adds to `app.json` were left out: without options both plugins do nothing, and listing expo-splash-screen could stop the automatic splash setup. These checks do not establish a signed build or physical-device acceptance.

Mac app (`mac/`): Swift 5 language mode, macOS 14+, SwiftUI with an AppKit `NSStatusItem` (click opens the window, right-click opens a menu), no Xcode project. `mac/build-app.sh` runs `swift build`, assembles `OpenPocket.app` (bundle `com.nestorcodecrafters.openpocket.mac`) with Pocket Mic, Instrument Serif and the default location samples in Resources, and signs it ad hoc by default; `SIGN_IDENTITY` signs the driver then the app with that identity, the hardened runtime and a timestamp, `UNIVERSAL=1` builds arm64 + x86_64, `BUILD_NUMBER` sets CFBundleVersion. `APP_STORE=1` builds the sandboxed TestFlight variant: `-DAPP_STORE` (`Distribution.appStore` gates the Pocket Mic install, the shell action and Shortcuts-by-URL), its own `.build/app-store` scratch path, bundle ID `com.nestorcodecrafters.openpocket` (the iPhone App ID, so the same App Store Connect app, like Usual Bot), and `OpenPocket-AppStore.entitlements` (sandbox, Bluetooth, read-only exception for OpenWhispr's folder). `mac/testflight.sh` builds it signed with Apple Development and has `xcodebuild -exportArchive` (`app-store-connect`) re-sign with cloud-managed Apple Distribution + Mac Team Store profile and upload; `mac/xcode-export.sh` (shared) wraps the SwiftPM app in a minimal `.xcarchive`. `mac/release.sh` (see `docs/mac-release.md`) wraps it for the notarized download: Developer ID for team G6WL4CPNV3, UTC-time build number, fresh driver build, signature checks, then notarization through Xcode's signed-in account (no password/API key): the app is wrapped in a minimal hand-made `.xcarchive`, `xcodebuild -exportArchive` (`developer-id`, `destination=upload`) uploads it, and `-exportNotarizedApp` is polled for the stapled app; then `spctl` and a zip of the stapled app (not a DMG: xcodebuild can't notarize one, and `spctl` rejects an un-notarized DMG). No entitlements are set; the sandbox is off by design. 2026-11-20: `--check` passed (universal, minos 14.0, Developer ID + runtime + timestamp on app and driver; the signed app ran `--snapshot`), and a trial notarization through Xcode's account was accepted within about a minute (`stapler validate` ok, `spctl` "Notarized Developer ID"). CoreBluetooth talks to the documented command and audio characteristics only. The key is the Keychain item service `heypocket` / account `session-key`, shared with the CLI, and is to move to a team keychain group with iCloud sync. Dictation uses CoreAudio default-input switching (the previous input UID is saved first and restored on the next launch after a crash), CGEvent hotkeys (Accessibility), and an AudioFileStream + AVAudioConverter MP3 decoder feeding AVAudioEngine pinned to the Pocket Mic output. Gestures use a Swift port of the prototype detector (1 ms level track, peak attack/sustain, clustering), a heuristic gesture confidence, a 40-band fingerprint, and softmax logistic regression for location. Rules and settings live in UserDefaults. Calibration samples and kept sessions live in `~/Library/Application Support/heypocket/`. The Command Line Tools SDK has no SwiftUI macro plugin, so the views use `Box` + `@StateObject` instead of `@State`. `OpenPocket --snapshot <dir>` renders the screens via ImageRenderer. `--gesture-test`, `--train-locations` and `--loopback-test` are offline checks. Pocket Mic (`driver/`) is a CoreAudio AudioServerPlugIn loopback device (48 kHz stereo float, sample-time ring buffer that reads silence outside the written range) on vendored libASPL (MIT), built by `driver/build.sh` with clang. `driver/install.sh` or the app's Setup copies it into `/Library/Audio/Plug-Ins/HAL` and restarts coreaudiod.

Expo 57 / React Native 0.86 / TypeScript / Expo Router / HeroUI Native 1.0.9 / Uniwind. Use npm and the compatible Expo native dependency set.

`PocketClient` serializes device operations; react-native-ble-plx owns BLE. Pure protocol and inbox modules validate replies, counts, file sizes, and completion. Swift Expo module owns hotspot configuration, Wi-Fi TCP streaming, and the one-shot 127.0.0.1 OAuth relay (Pocket only registers HTTPS or loopback redirects, not custom schemes). Config plugins persist entitlement/Local Network usage copy through prebuild, and `with-ble-write-ready` runs `plugins/patch-ble-write-ready.rb` from the Podfile post_install hook to patch MultiplatformBleAdapter 0.2.0 so write-without-response writes immediately; unpatched, it waits for a `peripheralIsReady` callback iOS never sent after Pocket's first command (verified on device, firmware 1.8), so every later command hung. Never enable verbose BLE logging outside a local debug session: it prints raw writes, including the device key. The patch fails `pod install` if the library source changes. iOS 27 kills apps built with its SDK at launch unless they adopt the UIScene life cycle (`_UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption`, seen on device 2026-10-31); Expo SDK 57's template does not, so `plugins/with-scene-lifecycle.js` (ported from Still) adds a scene manifest using `EXExpoAppSceneDelegate` and makes `AppDelegate` an `ExpoReactNativeFactoryProvider` that no longer creates its own window. It fails prebuild if the Expo AppDelegate template changes; remove it once Expo adopts scenes. OAuth return, deep links and universal links under scenes still need device acceptance. Run `pod install` with a UTF-8 locale (`LANG=en_US.UTF-8`) or CocoaPods fails after prebuild. Generated `ios/` is not tracked; `app.json` declares bundle ID `com.nestorcodecrafters.openpocket` and the signing team so prebuild preserves that identity.

SecureStore contains the verified device credential with saved peripheral identity, plus at most one unverified candidate key (cleared on verification or forget). Pocket OAuth/API tokens are not stored. A separate device-only Keychain record holds ChatGPT's stable host ID, issued client/account mappings, active account, and token sets. `ChatGPTProvider` owns the independent account client; it serializes account changes and rotating refresh tokens and renews the active session on launch/foreground and once per minute while active when expiry is near. Native `ChatGPTIdentity` uses Apple Security RS256 validation against OpenAI JWKS before identity is trusted. Local MP3s and a small metadata index live in Documents/recordings; app settings live in Documents/settings.json. The ble-plx plugin enables the iOS `bluetooth-central` background mode so Bluetooth downloads continue after the app is backgrounded. Expo Audio and Sharing provide playback/export. Account HTTP calls handle authorization/identity only; no app backend exists.

`TranscriptionProvider` owns a separate controller for BYOK credentials, selected provider, one active operation, and transcript/job state. A third device-only Keychain record stores provider keys; secrets never enter its UI snapshot. Documents/transcripts uses the same fresh-name snapshot publisher as the recording library. Adapters send the user's chosen model per provider (defaults: OpenAI `gpt-transcribe`, Deepgram `nova-3` with model-improvement opt-out, AssemblyAI automatic `universal-3-5-pro`/`universal-2`, ElevenLabs `scribe_v2`, Groq `whisper-large-v3-turbo`). `src/lib/transcription/models.ts` owns discovery: GET model listings (OpenAI/Groq/Deepgram) filtered to file-transcription models, or key verification plus a documented list (ElevenLabs/AssemblyAI), all through the same trusted-URL, no-redirect, bounded JSON helper. Model IDs are plain identifiers (validated, URL-encoded for Deepgram). Choices persist as optional `models` in the transcription Keychain record (older records load unchanged); discovered lists stay in memory. Research: `docs/research/transcription-providers.md`. App upload limits are 25 MB for OpenAI/Groq and 500 MB for the others (10 hours for AssemblyAI/ElevenLabs). The independent `pocket-transcription` native module streams audio uploads from disk, rejects redirects, bounds responses, and handles cancellation. JSON submission/polling uses `expo/fetch` with redirects disabled. Existing dependencies suffice. Real provider acceptance and quality are unverified by synthetic tests.

`NotesProvider` owns the user-written notes in Documents/notes (renamed from the earlier editable "summary" on 2026-11-01; no saved summaries existed, so there is no migration and no `summary-*` iCloud compatibility), keyed to the same relative recording identity as transcripts. Saves are serialized, bounded to 100,000 characters, and create UUID revisions with monotonic timestamps. `ICloudProvider` composes the independent library/transcript/notes owners through a pure account-consent controller and reconciliation engine. Its enabled preference and opaque Apple-account binding are device-only Keychain data. The `pocket-icloud` Expo module uses `NSMetadataQuery`, coordinated file operations, bounded disk streaming, SHA-256, and revocable account-bound sessions. Cloud folders are a folder per day holding one readable folder per recording, `YYYY-MM-DD/HH.MM` plus ` – <AI title>` once a summary exists (` (sha6)` is inserted when another recording already holds that name; top-level recording folders from older layouts are still recognized and moved into their day folder, keeping any title in their name; native scan reads two levels; empty day folders are removed after moves; titles drop `/ \ :` and control characters; names ≤ 200 UTF-8 bytes). Identity is the audio checksum in each folder's `recording.json`, never the name: every run reads all manifests first, publishes into whichever folder already holds the recording, imports per checksum across all its folders, and finally, via native `moveFolder` (coordinated move, or merge that moves missing archive files and removes only downloaded byte-identical duplicates), merges duplicates and renames OpenPocket-named folders (legacy `date_timestamp-audioSHA`, or names starting with the recording's date and time, nested or top-level) to the newest title, else the title the folder already carries; folders renamed by people are left alone, and a title is never removed. Pocket timestamps are `YYYYMMDDHHMMSS`, or `PH` + `YYMMDDHHMMSS` on some firmware 1.8 recordings; recording IDs keep the recorder's form. Each folder holds `audio.mp3`, `recording.json`, immutable `transcript-SHA.json`/`.txt`, `note-SHA.json`/`.md`, and `summary-SHA.json`/`.md`. Audio is limited to 2 GB; JSON to 8 MB. Audio, metadata and text share one folder, so native publication reuses an existing recording directory (creating it only once). iOS reports the container as `/private/var/…` in listings/metadata but `/var/…` after symlink resolution (how the root is built); `ICloudPolicy.relative` compares paths without that alias, the metadata query matches both forms, and scan deduplicates by relative path. Native emits `change` only when a file was actually written or the per-file state signature (downloaded/uploaded/conflict/error) changes, never for upload progress or identical re-publication; otherwise sync re-triggers itself about once a second. Every counted per-file sync failure is written to the Debug log as `icloud: <context>: <message>`; unexpected native system errors surface as `E_ICLOUD_FILE` with their `(domain code)` appended. Native verified imports publish `Documents/recordings/icloud_SHA.mp3`, then share the library's serialized index publication with recorder downloads. Imported text requires no API credentials; unfinished jobs and unsaved local results are preserved.

`plugins/with-icloud.js` configures CloudDocuments entitlements and public Files/Finder visibility for `iCloud.com.nestorcodecrafters.openpocket`, including `OpenPocketICloudContainerIdentifier`. The Apple developer App ID must have iCloud enabled and this container assigned, with a refreshed provisioning profile. No CloudKit database, backend, environment secret, or data migration is required. Existing libraries stay local until the user opts in. After this native/configuration change, apply Expo prebuild, run `npm run ios:pods`, and rebuild/install the signed app; JavaScript reload alone is insufficient.

`AiProvider` (inside `TranscriptionProvider`) owns AI titles/summaries via `src/lib/ai/controller.ts`. Settings and keys live in a separate device-only Keychain record (`openpocket.ai.v1`: selected provider, OpenAI/Anthropic/OpenRouter keys, model per provider, `autoSummarize` consent provider); summaries in `Documents/ai-summaries` snapshots keyed by recording identity. iCloud syncs them as `summary-SHA.json` (`schema, kind, title, text, updatedAt, provider, model`) plus a readable `summary-SHA.md` (`# title`, then text); the newest `updatedAt` wins with a payload tie-break (`compareSummaries`), merges go through `AiController.mergeSummary` with the run's expected local entry, and automatic summaries skip iCloud-imported recordings. ChatGPT requests use `ChatGPTProvider.planToken()` (renews, then returns the access token only with `chatgpt.tokens.use.direct` + `resource.invoke`) against `POST api.openai.com/v1/responses` with `stream: true`, `store: false`, no output limit, and `input` as a list of message items (a plain string gets HTTP 400 "Input must be a list"); only `response.completed` counts, and its text is rebuilt from `response.output_text.delta`/`.done` events when the completed event has no output (observed on device 2026-11-01). Without a chosen model the controller first fetches the provider's list and uses the recommended model only if listed, else the first listed one. Failures are logged to the Debug log as `ai: <context> (<model>): <message> (<provider detail>)`, where detail is the HTTP status plus bounded error code/type/param/message or a 300-character body excerpt; parse failures log only the reply's shape, never generated text. OpenAI uses the same endpoint without streaming (`store: false`, 3,000-token cap); Anthropic `POST /v1/messages` (`x-api-key`, `anthropic-version: 2023-06-01`); OpenRouter `POST /api/v1/chat/completions` always with `provider: { zdr: true, data_collection: "deny" }`. `src/lib/ai/request.ts` allows only those endpoints plus each `models` list and OpenRouter `auth/keys`, refuses redirects, bounds bodies to 2 MB and maps provider errors (plan limits, workspace-less Claude keys, no ZDR route) to fixed messages. One request per transcript up to 400,000 characters (no chunking); output must start with `Title:`. OpenRouter sign-in reuses the `PocketOAuthLoopback` localhost relay as its documented callback. Research and open questions (App Store eligibility for ChatGPT plan usage, model names): `docs/research/ai-providers.md`.

UI helpers: `@gorhom/bottom-sheet` (JavaScript, needed by HeroUI `BottomSheet`; installed 2026-11-01 after the page-sheet workaround) backs the shared content-sized `Sheet`; `HeroUINativeProvider` must stay innermost in `src/app/_layout.tsx` because HeroUI portals render at the provider, outside any context below it. `react-native-enriched-markdown` 1.1.1 (Software Mansion, native, New Architecture; added 2026-11-01) renders and edits note Markdown; the app `package.json` `enriched-markdown` block disables code highlighting, math and video so `postinstall` downloads nothing extra and pods exclude them (changing it needs `pod install` and a rebuild). `expo-clipboard` (native module, added 2026-11-01; needs a rebuilt app) backs Copy text; `react-native-keyboard-controller` (`KeyboardProvider` in the root layout) backs the shared `Screen`, a `KeyboardAwareScrollView` that keeps the focused field above the keyboard. ESLint ignores the generated, git-ignored `.expo/` folder.

ChatGPT uses the documented open-source/local flow: `dynamic_agent_client` only for first registration, issued `oaiapp_…` IDs for exchanges/reauthorization, stable `ext_agent_host_id`, S256 PKCE/state/nonce, and the fixed `auth.openai.com` endpoints. It requires no backend, developer API key, or client secret. Hosted/commercial distribution has a separate registration contract; recheck before changing deployment scope.
