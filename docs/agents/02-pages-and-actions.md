# Pages and actions

- Start route (`src/app/index.tsx`): waits for the saved recorder to load, then opens Settings while no recorder is saved (setup lives there) and Recordings afterwards. There is no Home tab; tabs are Recordings and Settings. The light/dark toggle is in the Settings header. The recorder lives at the top of Settings (`src/components/recorder-section.tsx`, "Recorder" / "Set up your recorder" section with the activation note as footer): until a verified connection is saved, it shows a three-step setup stepper (sign in or import a key → scan and select a recorder → connect and verify); done steps turn green with a check, upcoming steps are dimmed. Afterwards shows a compact recorder card (device drawing full height on the left; chip with a ⋯ menu, name, and `battery · firmware` or a nearby/awake hint on the right; the HeroUI `Menu` holds Disconnect/Reconnect and a danger-styled Forget this recorder, which returns to setup): status chip that also carries recorder work in progress (Connecting…, Checking recordings…, Saving recordings…, Disconnecting…, Forgetting…; otherwise Connected / Not connected) — no separate status line once setup is done, switch theme.
- Recordings: with no recorder saved and no recordings, a "Set up your Pocket" card whose Set up Pocket button opens Settings (setup steps); with a recorder but no recordings, "No recordings yet"; otherwise (no banner, even while disconnected) one grouped list (`Section` header + HeroUI `ListGroup`) per date; each row shows the AI title or time, then time · duration (or duration), a saved/on-Pocket/saving icon and a chevron, merged by `src/lib/pocket/recording-list.ts`; each opens `recordings/[id]` (ID is `date/timestamp`, passed URL-encoded). The recording page has the time as title, date · duration subtitle, header Share MP3 for the latest local copy, a player (draggable HeroUI `Slider` position with elapsed/remaining time, 5-second back/forward, large play/pause; nothing autoplays), a still-on-Pocket/saving note when not saved, and separate Transcript, Summary and Notes cards. All in-page actions are small secondary icon-and-label buttons (`ActionButton`), never ghost or primary. A refresh icon in the header (shown while connected; a spinner while listing) re-reads the device listing. There are no manual transport controls. Each downloaded copy also offers transcription with the configured provider, a confirmation naming the cloud upload and API billing, progress/cancel, and a four-line transcript preview: a copy icon at the card's top right (system clipboard via `expo-clipboard`; it briefly turns into a checkmark), and, only when the text runs past four lines (measured by an invisible unclipped copy, since iOS reports only the visible lines of a clipped Text), a fade into the card (react-native-svg gradient in the style of HeroUI's ScrollShadow) and a centered ghost Show more directly under it opening the full selectable transcript in a bottom sheet whose actions are Close and Copy text. Missing keys link to Settings. Failed local transcript saves retain the result in memory with Save transcript; this action never uploads again.
- Recording → Summary: read-only AI title and summary, rendered as Markdown with the notes' styling. With a finished transcript and a connected AI provider: Summarize with <provider> under the text, or, once a summary exists, a Rewrite icon at the card's top right in place of the sparkle (native confirmation naming the provider and billing; transcript text only), progress with Cancel, failure message, and "Written by <provider> · <model>". Without a transcript it says to transcribe first; without a provider it links to AI settings. A saved title replaces the time as the recording page's large title (subtitle adds the time) and as the list card's main line (time · duration below).
- Recording → Notes: saved notes render as Markdown (`EnrichedMarkdownText`). Add note (under the empty state) or the edit icon at the card's top right opens a full-screen page-sheet Markdown editor (`src/components/note-editor.tsx`, Software Mansion `EnrichedMarkdownTextInput`): Cancel (asks before discarding changes; swipe-to-dismiss is off) and Save in the header, a toolbar pinned above the keyboard (bold, italic, strikethrough, heading, bulleted/numbered list, outdent/indent, highlighted when active), and typing shortcuts (`# `, `- `, `1. `). Save publishes the Markdown locally, Cancel keeps the saved version, and saving empty text intentionally clears it. Failed saves retain the draft. A synced revision or a change of the selected local recording copy requires reviewing the current notes before keeping the draft over it. Notes make no model request and work without ChatGPT or transcription credentials.
- Setup also shows an optional ChatGPT card below the three recorder steps; connecting or skipping ChatGPT does not affect recorder setup completion.
- Tab stacks with pushed pages (Settings, Recordings) export `unstable_settings.initialRouteName = 'index'`, so a page opened from another tab or a link still has the tab's main page underneath and a back button. Settings: iOS grouped list rows (no cards). "Recordings" group: Download new recordings (switch, default on, persisted in Documents/settings.json; status line; ⓘ opens the Learn more page sheet) and iCloud sync (switch, status line with spinner while working, ⓘ details sheet; errors and Retry saving Off render under the group). "Transcripts" group: Transcription and AI chevron rows showing provider · model (· Automatic). The Transcription row pushes `settings/transcription`: iOS-style grouped sections — Provider (HeroUI `ListGroup` radio rows with checkmark, key status and size limit), `<Provider> API key` (description and model; when saved a status card with Replace/Remove, otherwise a secure field with Save key), a Model section once a key is saved, an Automatic section, and `<Provider> account` link rows (API key, pricing, privacy). Opening a provider with a saved key (once per session), saving a key, or tapping Refresh runs a read-only check with that key. OpenAI, Groq and Deepgram return the speech models the key can use; ElevenLabs and AssemblyAI verify the key and offer their documented models. A rejected key or an unreachable provider is explained, and documented models stay selectable. The chosen model is saved per provider in Keychain and sent with each transcription; the Settings card shows provider · model (· Automatic when on). Automatic: a "Transcribe automatically" switch (disabled without a key). Turning it on shows a native confirmation naming the provider, billing, and how many recordings are waiting; consent is stored as `autoTranscribe: <provider>` in the Keychain record and only applies while that provider is selected. `src/lib/transcription/auto.ts` picks recordings: the latest copy per recording ID, newest first, with no transcript entry, excluding iCloud imports (their other device may have transcribed them). `TranscriptionProvider` calls `controller.autoTranscribe(library)` 3 s after the library or transcripts settle; each recording is tried once per app session. A pre-check failure (too large, missing audio) skips that recording; a failed request leaves an error entry (never retried automatically) and pauses automatic transcription until the app returns to the foreground. Backgrounding cancels the active upload as for manual transcription. Errors with Dismiss, loading/saving, and active-transcription lock notices sit above the sections. The AI row pushes `settings/ai`; the AI page has Provider (ChatGPT, OpenAI, Claude, OpenRouter), the credential (ChatGPT: the ChatGPT account card with Continue with ChatGPT / account actions; others: API key card; OpenRouter also has Connect with OpenRouter, a PKCE sign-in that saves the issued key), a Model section once connected (live list; OpenRouter's long list is searchable and shows prices), Automatic ("Summarize automatically", confirmed once per provider; newest unsummarized transcripts one at a time while open; never retried; pauses after a failure until foreground), and account links. The ChatGPT card moved from Settings into this page; account connections remain accessible after recorder setup. Continue with ChatGPT adds a registration, saved-account actions reauthorize it, and Sign out attempts remote revocation then removes local tokens while retaining the account/client mapping. Failures explain when remote sign-out is unconfirmed. Manage usage opens `https://chatgpt.com/settings/usage`.
- Settings → Transcription: select OpenAI, Deepgram, AssemblyAI, ElevenLabs, or Groq; save/replace/remove a masked API key; open provider key, pricing, and privacy pages. A saved key has not been validated by a paid request. Saving never uploads audio. Removing a local key neither revokes it nor deletes remote content. Keys/providers cannot change while a transcription is active.
- Settings → iCloud sync: an off-by-default switch confirms copying the library to the current Apple account's iCloud Drive. The card is minimal: title, switch, one status line (progress stage, Off, or Last synced date/time), errors, and Learn more. Learn more opens a native iOS page sheet (`Modal` `presentationStyle="pageSheet"`, swipe down or Done) with the Files/Finder location, account and opt-out explanations, pending/conflict counts, and Sync now. Account changes require enabling again. Turning off immediately stops new app work; failed preference persistence offers Retry saving Off, and Apple's already queued transfers may continue. Files/Finder shows iCloud Drive → OpenPocket → recording folders with MP3 audio and readable transcript/note versions. Edit notes in OpenPocket; changing the exported TXT/Markdown copies does not edit app state.
- Settings → Debug (`settings/debug`, a chevron row in the last Settings section, Troubleshooting, whose footer shows "Open Pocket <version> (<build>) · unofficial, not affiliated with the maker of Pocket"; formerly its own tab): bounded connection/transfer history and redacted text export.
- OAuth callback: Pocket and ChatGPT redirect to `http://127.0.0.1:<port>/callback`; the native relay 302-forwards it to `openpocket://oauth/callback`, which the auth session captures. A shared lock permits only one sign-in at a time. The route only redirects to Home if opened directly.

Automatic download (default): while the app is active, PocketContext quietly reconnects the saved recorder (immediately on launch, foreground, or link loss, then every 30 seconds until it answers; a manual Disconnect pauses this until Reconnect/connect), downloads every listed recording without a local copy over Bluetooth (newest first, one at a time), and re-lists every 2 minutes while connected. Automatic failures are logged, not alerted; a failed or cancelled recording is skipped until the next connection. There is no manual download UI; Wi-Fi transfer code remains but is not reachable from the UI. Transfers run one at a time. Bluetooth transfers continue in the background (`bluetooth-central` mode); leaving the app cancels a Wi-Fi transfer. Wi-Fi uses the recorder's hidden hotspot and leaves it after each attempt. Library files survive disconnection and forgetting credentials.

Transcription runs one operation at a time while the app remains open, with no automatic retries. Backgrounding cancels local work; remote processing/billing can continue. AssemblyAI upload → submission → persisted job ID → polling is recoverable through Resume, even after restart or selecting another provider. Failed/expired jobs allow an explicitly confirmed fresh attempt. Other interrupted requests may already have been billed; retry confirms a new upload. Completion is associated with the recorder ID, relative audio filename, and exact byte count, so a replaced recording does not inherit the wrong text. No live provider audio has been sent during automated validation.

iCloud reconciliation runs while OpenPocket is active, after durable library/text changes, on foreground/native iCloud changes, and periodically (25 seconds). It publishes local versions before merging remote text, verifies imported audio, and adds it to the same saved library without needing a recorder connection or API key. Edits made during a run are retained for the next run rather than overwritten before archival. Unavailable downloads remain pending; existing conflicts are retained for review. There is no automatic deletion propagation or manual conflict-resolution UI. A completed check reports this device's state, not delivery to another device.
