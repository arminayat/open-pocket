# Design system

HeroUI Native supplies cards, buttons, form fields, chips, and progress spinners. Uniwind supplies light/dark tokenized backgrounds, surfaces, text, separators, and states. Main navigation is Expo Router native tabs: Recordings (the main tab) and Settings (Debug is a page inside Settings; the theme toggle is in the Settings header). Each tab is a native stack with an iOS large title that collapses into the standard bar on scroll (`TabStack`); screens set dynamic titles and header buttons with `Stack.Screen` options, and `Screen` content uses automatic content insets with no top padding, so the optional subtitle sits directly under the large title's own bottom padding. No in-content titles or eyebrows. The Home recorder card shows `PocketDevice` (`src/components/pocket-device.tsx`), an SVG front view of the grey Pocket (card-shaped aluminium slab, engraved serif wordmark reading bottom to top, side button, LED pinhole that turns green when connected), drawn from the vendor's product photos; it fills the card's left side at 84 pt wide, and the right column spans the drawing's height, with the chip/name header at the top and a muted `battery · firmware` line pinned to the bottom, plus a ⋯ overflow `Menu` for the rare Disconnect/Reconnect and Forget actions; no full-width buttons). Setup uses a vertical stepper (`src/components/setup-steps.tsx`): numbered circles joined by a line, green success check when done, dimmed cards for upcoming steps.

Use safe-area-aware screens, readable Inter text, system font scaling, accessible control labels, and explicit errors. Pocket context errors appear as a single native `Alert` (`ErrorAlert`, mounted at the root); dismissing it clears the error. Small local errors (share, export) stay inline. Explain connection prerequisites, cloud sign-in permission, temporary hotspot joining, and foreground download requirements in ordinary language. Keep raw protocol details in diagnostics rather than everyday flows.

App icon: an Instrument Serif "P" (the title font) drawn as a dashed near-black outline, with no fill, on opaque white. It is generated by `scripts/app-icon.swift` (`npm run icon`; 18 px stroke, 28/26 dashes at 1024 px) and was checked at 180 px. Like the Pocket icon, the letter is oversized: it starts 22% from the top, spans about 22–78% of the width, and its stem runs off the bottom edge, so the foot serif is cropped. It deliberately echoes the official Pocket icon, a filled serif P on white; recheck the trademark risk before any public release.

The Settings recorder card shows an SVG front view of the recorder (`PocketDevice`), tinted by the finish read from the recorder name (`recorderColor`, e.g. `PKT01_GREY_…`): Space Grey, Sierra Blue, or Baby Pink, the three finishes sold on heypocket.com. Unknown names fall back to grey. Only the GREY name token is confirmed on hardware; the blue and pink tokens and palettes are inferred from store photos.

ChatGPT uses a reusable optional card below recorder setup and in Settings, with Continue with ChatGPT, distinct stable account labels, active/expired/plan-disabled states, reconnect/sign-out actions, and a usage link. Its inline errors and progress are accessible and separate from Pocket alerts. Explain that ChatGPT-powered features are not yet available, transcription needs a separate API key, and sign-in uploads no recordings; never make this an extra required recorder setup step.

Transcription Settings uses compact provider buttons, a masked key field, saved status, and pricing/privacy links. Recording cards show the selected provider in the Transcribe action; a native confirmation states cloud upload, separate API billing, and keep-open requirements. Known jobs say Resume; ambiguous retries warn about another possible charge. Progress and errors stay inline, with selectable expandable text and text sharing after completion. Do not claim a saved key is connected/verified or that cancellation deletes remote work.

The recording page shows a compact player directly on the page background (no card; 48 pt play button and 24 pt skip icons just under the track), then Summary, Notes and Transcript cards (in that order), each with a `Card.Title` header. Actions use `ActionButton` (size sm, secondary, Ionicon + label); do not use ghost or primary buttons there. The transcript card has no provider label; it shows four lines fading into the card, a centered ghost Show more right under them, and a copy icon at the card's top right. The Summary card renders Markdown and its Rewrite is an icon at its top right (the sparkle shows until a summary exists); the Notes card's edit action is likewise a top-right icon; the full text opens in the shared `Sheet` (native page sheet, also used by Learn more). Summary is read-only and marked as AI-written (sparkles icon, "Written by <provider> · <model>"); its only actions are Summarize / Rewrite and Cancel. Settings pages share `src/components/settings-parts.tsx` (Section, ChoiceList with search for long lists, ApiKeyCard, LinkRows, ErrorRow). Notes are labelled as the user's own and render as Markdown; Add note / Edit opens a full-screen page-sheet editor with Cancel/Save, a formatting toolbar above the keyboard (active formats in the accent color) and Markdown shortcuts. Keep drafts visible on save errors; if a synced revision or selected recording copy changes, disable saving until the user reviews the current version and explicitly keeps the draft. Empty text clears the saved notes through an ordinary revision.

iCloud Settings is a separate card with a switch, a native opt-in confirmation, Sync now, readable progress/errors, pending/conflict counts, and last-check time. Explain the Files/Finder path, same Apple account requirement, device-only credentials, preserved older versions, and non-destructive opt-out. Say that Apple controls transfer timing; never label a local check as successful delivery to another device. Account changes require renewed opt-in, and failed opt-out persistence has a visible retry action. Note editing remains in the app; exported TXT/Markdown copies are readable artifacts.

Settings and the Recordings list use iOS grouped `ListGroup` rows inside `Section`s, not cards: title, one status/description line, and a trailing control (switch, ⓘ `LearnMore icon`, or chevron for pushed pages). Rows inside a card are 8 pt apart (`gap-2`); controls in the title row must not add height (Manage uses `-my-1.5`). Every description sits behind `LearnMore` (`src/components/learn-more.tsx`), a compact text link (no taller than the status line, 12 pt hit slop) opening the shared `Sheet`. Larger settings get their own pushed page (Transcription → Manage), laid out as iOS grouped sections: small uppercase muted section headers, HeroUI `ListGroup` rows with `Separator`s (checkmark for the selected option, open-outline icon for external links), and muted footers. HeroUI `BottomSheet` is not usable: its optional `@gorhom/bottom-sheet` peer is not installed, so `BottomSheet.Content` is undefined at runtime and crashes the tree. HeroUI `Menu` with `presentation="popover"` does not need it.

Typography: every title uses Instrument Serif (`@expo-google-fonts/instrument-serif`, `TITLE_FONT` in `src/components/screen.tsx`, loaded with Inter in the root layout): native large and inline header titles via `TabStack` `headerLargeTitleStyle`/`headerTitleStyle`, HeroUI `Card.Title` through a `.card__label` override in `global.css` (24/28, regular weight), and sheet/editor titles. Body, labels, list rows and small uppercase section headers stay Inter.

Sheets: `src/components/sheet.tsx` is a HeroUI `BottomSheet` (`@gorhom/bottom-sheet` 5.2.14) sized exactly to its content; `scrollable` sheets (the full transcript) use a fixed 85% snap point with a `BottomSheetScrollView` above the actions, because a scroll view inside HeroUI's measured content container breaks dynamic sizing (the sheet came out too short and hid the actions), with a title and, at the bottom in one row, a secondary (Close) and a primary action, or a single Done when a sheet has no action of its own; HeroUI's content container supplies the only padding. Swipe down or tap the overlay to close. Actions sit 24 pt below the content. Sheet copy is one short `SheetLead` sentence plus 3–4 `SheetPoint` rows (muted icon + one short idea each), with status in a single muted xs line; avoid paragraphs of caveats. The full transcript's primary is Copy text; the iCloud sheet's primary is Sync now (while sync is on). Used by Learn more and the full transcript. The Notes editor stays a full-height React Native `pageSheet` modal. `HeroUINativeProvider` is the innermost root provider so portal content (sheets, menus) can read app contexts.
